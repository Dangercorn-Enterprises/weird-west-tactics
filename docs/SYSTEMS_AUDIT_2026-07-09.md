# DUSTFALL systems audit — 2026-07-09 (the "is there a game in here" audit)

Triggered by Tim's push: balancing, loot, inventory, character sheets, equipment,
upgrades, dialogue, story, random encounters, FFT-style traversal, and whether
character creation actually means anything. Six parallel auditors read the Godot
port AND the web original; every claim has a file:line receipt. Ruthless-honesty
brief; EXISTS = works, PARTIAL = shallow/stub, MISSING = absent.

HEADLINE: solid parity-tested combat engine + real buy/equip/fight loop, wrapped
in a 2-4 hour single-path campaign. 5 of 9 stats dead, no character sheet, no
loot drops, no dialogue system, no LOS, all 5 bosses one enrage template, map is
node-hop not FFT-walk. One true PORT REGRESSION: shrine god-swearing is a no-op
(party_to_unit drops p['god'] — one-line fix). Three unwired systems already in
the repo answer much of it: src/haunts.js (procedural encounters+loot),
map_gen.py (5 board types), encounter_gen.py (scaled encounters+loot+hooks).

CLUSTER 1: World map traversal, random encounters, day/time, Quick Skirmish, difficulty/NG+/replayability (Godot 4.7 port vs web bu

EXISTS (8):
  - Worldmap node-graph traversal: 26 nodes / 36 edges loaded from design.json; click an adjacent node to travel (adjacency enforced), click current node to enter town. Travel is INSTANT node-hop — days = round(euclidean distance x 22, min 1) added to a day counter, modified by mount travelF (horse 0.6x, camel 0.55x, clockwork steed 0.4x). No FFT-style party movement along paths — the party never visibly moves; there is not even the web build's bobbing player token, just a white ring on the current node.
  - Random travel ambushes: each edge carries a risk tier (1/2/3 = road/trail/wilderness) -> 0%/30%/60% ambush chance on travel; mounts subtract ambushMod (-10% to -15%, floored at 5%). Ambush composition IS procedural: 2-3 enemies (+1 if destination tier>1) drawn randomly from non-boss enemies with tier <= destination tier (pool of 5 at tier-1 nodes, 10 at tier-2+), biome chosen from the destination's patron god.
  - First-arrival boss 'Reckonings' at tier-3 nodes: arriving at a tier-3 node for the first time triggers a boss battle (faction-matched boss + 2 minions). Five tier-3 nodes exist (deathvalley, salton, area51, losalamos, roswell); three are pre-claimed by story beats, so salton and roswell are genuine optional off-path boss fights.
  - Marshal bounties: repeatable, player-initiated random battles at any node with a marshal (7 nodes) — 2+tier random enemies from the tier-gated pool, pays 60+tier x 40 gold on a win via battle result context. This is the game's one grindable/repeatable content loop.
  - 3-act story spine on the map: 6 scripted beats (2 location-locked per act at losangeles/deathvalley, losalamos, area51; act-opening vanguard fights fire on the NEXT travel to any node). Objective text + pulsing gold marker on the target node; finale routes to an ending scene.
  - Rest/heal economy touching the day counter: saloon Rest heals the whole party and costs 1 day (no gold); Doc heals for 40 gold (no day cost); wounds persist between battles and the fallen survive at 1 HP (no permadeath, no game-over on loss — you just return to the map wounded).
  - Travel-cost preview: hovering a reachable node shows ride days, risk label (road safe / trail risky / wilderness wild), and node lore before you commit.
  - Demo build cap: export feature tag 'demo' cleanly caps the campaign at end of Act I, swaps the objective line to a demo-complete pitch, and keeps Act I map + towns + skirmish playable — real, tested branching, not a stub.

PARTIAL (5):
  - Day/time system — the counter exists but is DECORATIVE: state.day is only ever written (travel, rest) and displayed (HUD headers, ending credits 'Survived N days'). Nothing reads it: no supplies/food consumption, no day/night, no deadlines, no escalation, no time-based events. Resting and travel consume 'time' that costs nothing.
  - Quick Skirmish — one hardcoded battle, zero variety: always 'Skirmish at the Crossing', always mesa biome, always the same 4 enemies (walkin_dead, coyote_beast, forge_sentry, dust_devil). No biome pick, no random composition, no difficulty pick, no wave/endless mode. (The web main game's skirmish is equally fixed, so this is parity — but it means ~5 minutes of content.) The web title's second quick-battle button 'Boss: The Deacon' was NOT ported.
  - Map content beyond the story path: all 26 nodes have unique lore text, god alignment, tier, and service mix (saloon/outfitter/shrine/forge/stable/marshal/doc), and shrines differ by patron god — but only ~6 nodes have unique EVENTS (4 story nodes + salton/roswell reckonings). The other ~20 are shop-menus-plus-flavor-text: no side quests, no node events, no unique NPCs (recruits are random names from one shared 12-name pool; rumors are 5 canned strings). 'visited' state only changes node opacity on the map.
  - Encounter difficulty scaling — exists only as party-size scaling (core.scale_encounter scales enemy count/stats to party size) and tier-gating by destination node. There is no player-facing difficulty anywhere.
  - campaign_complete flag — written on finale victory but never read by any code: no post-game map state, no NG+, no unlocks. Ending returns to title; Continue reloads the completed save with nothing to do.

MISSING (7):
  - Difficulty options (no easy/normal/hard anywhere — settings.json holds audio prefs only; pause menu is resume/volume/mute/quit).
  - New Game+ or any post-campaign content/unlock.
  - Party movement along map paths / travel interruption mid-route (ambush resolves as if at the destination; you always arrive first, then fight).
  - Non-combat random events (no weather, no travel events, no node arrival events — the only random systems are ambush rolls, ambush/bounty enemy composition, saloon recruit, and rumor text).
  - Procedural map/encounter generation in-game: the repo contains a full unwired procedural stack — map_gen.py (5 seeded tactical map types: ghost_town, canyon, mine_shaft, desert_outpost, cursed_ruins), encounter_gen.py (level-scaled encounters with objectives, loot tables, narrative hooks), and src/haunts.js (726-line procedural 'Haunt' generator: 6 themes x 6 locations, tiers 1-5, per-haunt special rules, loot tables). NONE of it is referenced by the Godot port — and note it was never wired into the main web game (game.html) either; haunts.js only feeds the standalone haunts.html, and the .py tools are CLI-only. Battles in both builds use 6 fixed hand-authored biome boards from design.json.
  - Skirmish/arena mode with options: src/dustfall-arena.html is a separate standalone web prototype; no arena, wave mode, or configurable skirmish exists in the Godot build.
  - Loot/reward variety: ambushes and reckonings award only XP/favor (context {}); bounties award flat gold; no item drops, no random loot anywhere in the campaign loop despite loot tables existing in the unported haunts/encounter_gen systems.

NOTES: The headline surprise: worldmap parity with the main web game is genuinely complete — the Godot port is a near line-for-line translation of scene_worldmap.js including ambush odds, mounts, reckonings, and the demo cap. The gap is not port-fidelity, it is that the SOURCE design is thin on replayability: one campaign path (~6 story fights + 2 optional reckonings), a day counter nothing consumes, a single hardcoded skirmish, no difficulty, no NG+, no loot drops, and ~20 of 26 nodes being shops-with-lore. Estimated content: one 3-6 hour campaign run with near-zero variation between runs beyond your lead archetype pick and ambush RNG; the grind loop (marshal bounties) pays only gold, and gold has a low ceiling of things to buy. Meanwhile the repo already contains three unwired procedural systems (haunts.js, map_gen.py, encounter_gen.py) that directly answer the variety problem — wiring even one into Quick Skirmish or post-campaign bounties would be the cheapest playtime multiplier available. For a $10 Steam price point, the current loop is a demo-plus; the ambush/bounty plumbing is solid enough that variety injection is a data problem, not an engine problem.

CLUSTER 2: Story, dialogue, endings, campaign completeness (Godot 4.7 port vs Three.js web original)

EXISTS (7):
  - Full 3-act story spine with exactly 6 mandatory story battles, all implemented in worldmap.gd _story_beat(): (1) 'The Revenant Vanguard' on arriving Los Angeles at act1 step 0, (2) 'The Deacon's Reckoning' boss at Death Valley step 1, (3) 'The Forgeworks Vanguard' fires on the NEXT travel to ANY node once Act I is done, (4) 'The Iron Foreman' boss at Los Alamos, (5) 'Heralds of the Hollow Court' on any travel once Act II is done, (6) 'The Hollow Man' finale at Area 51 with a finale flag. Act steps advance only on a WIN (worldmap.gd:141-142), persist in the save (game_state.gd:123), and losses make the beat refire — this is full parity with the web version's act1Beat/act2Beat/act3Beat.
  - A real ENDING exists and is reachable: winning the Hollow Man fight sets flags.campaign_complete, saves, and change_scene's to ending.tscn (worldmap.gd:143-146). ending.gd shows a ~60-word authored epilogue paragraph, run stats (days survived, gold), a pantheon credits line, plays the win sting + map music, and returns to title (ending.gd:14-19).
  - Objective system: 3 authored objective lines per act (ACT1/2/3_OBJ, worldmap.gd:23-37), _objective_text/_objective_node pick the current line and target node (77-93), and the target node gets a pulsing gold ring on the map (198-200). Matches web scene_worldmap.js:30-132.
  - Battle intro narrative panels: each of the 6 story beats carries a 40-60-word authored intro; battle.gd builds a modal with title + prose + 'Ride' button that blocks all battle input until dismissed (battle.gd:679-704, gated at 941 and 1004). NOTE: this is an ADDITION over the web version — web beats pass no intro text and scene_battle.js has zero intro handling.
  - Campaign is padded by real optional systems: first-visit tier-3 node 'Reckoning' boss fights with faction-matched boss selection (worldmap.gd:263-280), risk-scaled trail ambushes with mount modifiers (282-296), and Marshal bounty battles that actually pay gold via battle context (town.gd:266-278, payout applied worldmap.gd:148-149).
  - Demo build gating works mechanically: OS.has_feature('demo') caps the campaign at end of Act I — Act II+ beats never fire, objective flips to a demo-complete pitch line (worldmap.gd:74-99), wired to the 'Windows Demo' export preset custom_features="demo" (godot/export_presets.cfg:54).
  - 26-node world with a one-line authored lore string per node (design.json:1524-1908), surfaced in the map side panel with ride-time/risk preview on hover (worldmap.gd:303-316). Same 26 nodes/36 edges as web worldmap_data.js.

PARTIAL (6):
  - Dialogue: there is NO dialogue SYSTEM in either version — zero branching choices, zero NPC conversations, no dialogue data in design.json (top-level keys are archetypes/stats/pregen/gods/enemies/weapons/armor/consumables/weapon_mods/mounts/biomes/world_nodes/world_edges — nothing story/dialogue shaped). All narrative is one-shot, non-interactive text: the battle intro modal has a single 'Ride' dismiss button (battle.gd:697-701) and town interactions print to a flash Label (town.gd:71-72). Nothing was lost in the port — but calling any of this 'dialogue' would be false.
  - Town 'Rumors — lean in close / Listen': 5 hardcoded one-liner strings, random pick, flash-text only — no state change, no quest hooks, no location awareness; one of the five is literally a gameplay tip ('High ground wins fights') (town.gd:30-36, button at 143). Byte-identical strings to web scene_town.js:92-98.
  - Ending variety: single fixed WIN ending only. The web version authored a loss variant ('THE FRONTIER FALLS' + loss prose, scenes_hub.js:177-183) — unreachable dead code in web too (act3Beat routes losses back to worldmap), but the port dropped the loss text entirely; ending.gd:14 hardcodes the win paragraph. No epilogue variation from god favor, party composition, or anything except the day/gold numbers interpolated into the credits line (ending.gd:17-18).
  - Defeat/game-over: there is no loss state anywhere. A party wipe shows a 'WIPED OUT' banner (battle.gd:1191) and returns to worldmap; fallen members are revived at 1 HP (game_state.gd:190-191 'the fallen cling on at 1 HP'). The campaign is mechanically unloseable. Side effect: beats 3 and 5 trigger on ANY travel, so after losing one of them the player is forced into the same rematch on every single map move until they win.
  - Post-campaign: after the ending the save persists with campaign_complete, so Continue drops you back into free roam with objective text 'The frontier is saved — for now.' (worldmap.gd:36, 89-90) and no marker — but there is zero post-game content, no NG+, and story beats are exhausted.
  - Story recap: none. Intro prose is shown once in a modal and is gone forever (queue_free, battle.gd:700-701); there is no journal, log, or way to re-read any beat.

MISSING (6):
  - Branching dialogue / choice system — does not exist in the Godot port (and never existed in the web version either; grep for dialogue/conversation/choice across src/ returns nothing).
  - Side quests / quest log — no multi-step quests anywhere; the Marshal bounty is a single immediate battle with a gold payout (town.gd:269-278). No quest state beyond the three act-step ints and boss flags.
  - The web 'Haunts' system was NOT ported: src/haunts.js (726 lines) + haunts.html is a procedural supernatural-encounter generator with its own expanded bestiary, 11 authored lore hooks, and per-haunt special_rule mechanics (src/haunts.js:1-30, special_rule blocks at 344/373/402/...). Zero references to it under godot/.
  - Loss-ending prose from web (scenes_hub.js:183) not carried over.
  - Companion/character story content — recruits are a random name from a 12-name list + random archetype + price (town.gd:127-142, NAMES at 27-29); no personal quests, barks, or dialogue.
  - Any cutscenes, act-transition screens, or opening crawl — a new game drops you on the worldmap at Catalina with only the Act I objective line (game_state.gd:120, worldmap.gd:24).

NOTES: Campaign math: exactly 6 mandatory battles, and BFS over design.json world_edges gives a 7-hop minimum route (catalina->losangeles->deathvalley->vegas->hoover->losalamos->hoover->area51); 6 of those 7 hops trigger story battles and the 7th has only an ambush chance, since the three tier-3 boss nodes on the route are exactly the story nodes whose generic reckonings get suppressed by boss_ flags. Playtime estimate: at a realistic 6-12 min per tactical battle, mandatory combat is ~45-70 min; add traversal/town/shopping (~15-30 min) and the near-inevitable grinding (starter duo + 300g vs the Deacon pushes players into recruiting/bounties/ambush XP) and an honest first playthrough is ~1.5-3 hours, with a practiced minimal run around 45-60 min. The Act-I demo build is 2 story battles, roughly 20-40 min. Total authored prose game-wide is ~1,400-1,600 words (6 beat intros ~280w, 9 objective lines, 1 ending paragraph, 5 rumors, 7 town flavor notes, 26 node lore lines, god/archetype blurbs) — about five book pages of writing for the whole game; the 'story' is functionally 6 well-written loading screens plus an epilogue card. Two surprises: (1) the Godot port is narratively RICHER than the web original — the beat intro prose and its modal presentation don't exist in the web build at all; (2) the game is unloseable by design (wipe -> revive at 1 HP -> retry), which combined with any-node triggers for beats 3/5 means losses convert into forced immediate rematch loops rather than setbacks. The port dropped two web things: the (dead-code) loss ending text and the entire 726-line Haunts procedural encounter/lore generator.

CLUSTER 3: equipment / loot / inventory / economy

EXISTS (7):
  - Item definitions with real mechanical stats: design.json defines 7 weapons (range/dmg/accuracy/cost, archetype gates on steam_cannon+hex_focus, ignoreCover on hex_focus), 5 armors (def/speed/cost), 6 consumables, 4 weapon_mods (stat-delta effect dicts), 3 mounts (travelF/ambushMod/cost). These are data, not flavor.
  - Shop purchase flow genuinely works: town.gd outfitter deducts gold and increments state['inventory'] then saves; buy buttons disable when broke so gold can't go negative. Forge sells all 4 mods the same way; stable sets state['mount'] and deducts gold; saloon recruits (90-160g), doc heal (40g), and shrine donation (50g) all move real gold.
  - Per-character equipment slots exist and are player-facing: each party member has gear {weapon, armor, mod} created at _mk_member; town.gd _cycle_gear cycles a rider through owned inventory items, returns the swapped-out piece to inventory, and enforces archetype gates (weapons) and faction gates (armor). The 'loadout UI' is the inline OUTFIT THE POSSE / FIT THE IRONS rows in the town outfitter/forge — same design as web, no separate scene needed for parity.
  - Equipped gear actually modifies combat numbers: combat_core.gd party_to_unit overrides dmg/range/accuracy from the equipped weapon, honors ignoreCover via wIC in do_fire, applies armor def as flat damage reduction in do_fire and do_blast (and battle.gd's item blast), applies armor speed to maxAp, and applies mod effect deltas to aim/rng/wmin/wmax. battle.gd builds player units from the real saved party via core.party_to_unit, so shop purchases flow into battle math end-to-end.
  - 3 consumables are usable in battle with real effects: battle.gd renders Bandage/Charge/Salts buttons from live inventory counts, and _use_item implements bandages (+8 HP, decrements inventory, saves), smelling_salts (revive fallen at 5 HP), and ashfall_charge (targeted 3x3 AoE 6-10 dmg, armor-reduced). Costs 1 AP each.
  - Gold loop that matters early-game: start 300g; sinks are gear/mods/mounts/recruits/doc/donations; income is marshal bounties (60 + town_tier*40) paid on battle win via context handoff worldmap._process_battle_result. Buying a rifle+vest for a new recruit is a real economic decision in Act I.
  - Mount ambushMod has a real mechanical effect: worldmap.gd reduces per-leg ambush chance by the mount's ambushMod (e.g. clockwork_steed -15%), meaning fewer forced fights — a genuine purchase payoff.

PARTIAL (5):
  - Catalog acquisition is capped at slice(): outfitter sells only weapons.slice(0,4), armor.slice(0,3), consumables.slice(0,3) (town.gd:187-189). ashfall_pistol, steam_cannon, hex_focus, blessed_vestments, clockwork_exo, tonic_vigor, holy_water, coyote_dust have NO acquisition path — no shop, no drop, nothing. NOT a port regression: the web build has the identical slices (scene_town.js:350-357), so 3/7 weapons, 2/5 armors, 3/6 consumables are dead data in BOTH versions. The archetype/faction gate code in _cycle_gear only ever guards items that can never be owned.
  - Flavor notes with zero mechanics: ashfall_pistol 'armor-piercing' (design.json:810) has no code — and enemies never get armorDef (enemy_to_unit, combat_core.gd:170-199), so armor-piercing could never do anything; blessed_vestments '+10% vs divine' (design.json:868) is read by nothing.
  - Consumables are hardcoded, not data-driven: battle.gd:793-838 switches on item id with baked-in numbers; design.json's effect/amount/radius fields are never read (values coincidentally match). The three unobtainable consumables' effect types (buff/antiundead/invis) have no implementation anywhere in either codebase.
  - Mount travelF is half-cosmetic: it scales travel days (worldmap.gd:238-244), but state['day'] is write-and-display-only in both versions — nothing consumes the day counter (no deadline, no upkeep, no per-day event roll). Ambush chance is rolled per-leg, not per-day, so faster travel avoids nothing. Only ambushMod delivers real value.
  - Economy loop degrades to a faucet: gold income is marshal bounty ONLY — story battles, ambushes, and boss reckonings pay 0 gold (worldmap.gd:148-149 pays only when ctx has 'bounty'; battle.gd:1188-1190 end-of-battle grants XP/kills only). Bounties are infinitely repeatable at fixed reward, so gold is grindable to arbitrary amounts and scarcity vanishes once the ~1,500g of buyable content is owned. No selling for gold (unequip returns the item to inventory, not cash).

MISSING (4):
  - Battle loot / item drops: zero item drops from any battle in the Godot port — victory grants XP + level-ups + (bounty-context gold) and nothing else. Web parity note: the web campaign also has no drops; the ONLY loot system in the repo is src/haunts.js loot_table entries (10+ haunts), and even there it is display-only bestiary content rendered by haunts.html ('Loot on Victory' cards) — generateHaunt passes loot_table through but no game code (game.html / scene_battle.js / scenes_hub.js) ever imports haunts.js or grants the items. So loot was never playable in web and was not ported at all.
  - Inventory/loadout screen: no inventory UI exists anywhere — pause_menu.gd has no inventory panel, scenes/ has no loadout scene; owned items are only visible as '(owned N)' suffixes on shop rows and consumable counts in the battle ability bar. You cannot inspect or re-equip gear outside a town with the right service tab.
  - Any secondary economy: no sell-back, no ammo, no repair/durability, no upkeep costs, no price variation by town ('Inventory varies by town' flavor text in web is false — the slice is constant).
  - Web character-creator.html edge/hindrance point economy (hindrances grant build points, incl. 'poverty: start with minimal equipment' — character-creator.html:839-846, 964-994) — not ported; godot creator.gd is archetype-pick + name only. (Caveat: that creator is a standalone HTML tool not wired into the web campaign either.)

NOTES: The headline surprise is that this cluster is at genuine PARITY with the web build — every gap found (unobtainable catalog tail, no loot drops, no inventory screen, hardcoded consumables, cosmetic day counter) is inherited from the web version, not lost in the port. The core buy→equip→fight loop is real and verified end-to-end: gold moves, inventory persists in the save, gear gates are enforced, and equipped stats provably change hit/damage/AP math in combat_core (the parity-tested balance path). Depth implication for the $10 Steam goal: the entire acquirable economy is 4 guns + 3 armors + 4 mods + 3 mounts + 3 consumables ≈ 1,500-2,000g of content, purchasable within a few bounty grinds; with no loot drops, no rare items, and no gold sink after full kit, equipment progression is exhausted by roughly mid-Act II and the marshal bounty becomes a meaningless infinite faucet. Cheapest wins already latent in the data: unlock the 3 premium weapons/2 premium armors at tier-2/3 towns (they're fully statted and gate-coded — hex_focus's ignoreCover and steam_cannon's archetype lock already work in combat), pay gold on story/ambush wins, and port haunts.js loot_table as post-battle drops. Also note enemies have no armor stat, so any 'armor-piercing' design is dead on arrival without an enemy armorDef field.

CLUSTER 4: Character creation + stat/ability meaningfulness (Godot 4.7 port vs web build)

EXISTS (5):
  - Character creator scene works and writes real state: pick 1 of 6 archetype cards (sprite art + bonuses text + desc/lore detail), edit lead name (prefilled from pregen), Begin calls GameState.new_game(archetype, name) and switches to worldmap. new_game writes a full campaign state (party of 2, gold 300, day 1, location catalina, favor seeds, act steps) and saves to user://save.json.
  - 4 of 9 stats feed real combat math: vigor -> HP (hp = 10 + vigor*2 - hpDamage); quickness -> max AP (3 + quick/4) and enemy-phase action order (sort by quick); deftness -> aim (weapon accuracy + (deft-5)*2) which drives hit_chance and the hover combat preview; strength -> +floor(str/3) flat damage on every attack roll and in the preview.
  - Archetypes differ mechanically, not cosmetically: distinct pregen 9-stat spreads (gunslinger deft 8 vs preacher deft 4), distinct default weapon (arch weapons[0]: Peacemaker 4-8/rng6/75% vs lawdog rifle 4-9/rng7/72% vs tinkerer Arc Pistol 5-12/58%), distinct hardcoded 2-ability kit (ABIL/ABIL2, e.g. gunslinger Fan the Hammer + Gut Shot vs preacher Lay on Hands + Holy Smite), distinct divine ultimate (DIVINE, e.g. Perun's Thunder AoE+stun vs Samedi's Embrace nuke+self-heal), distinct god favor pool (ARCH_GOD), and distinct level-up favored-stat pairs (FAVORED).
  - Progression loop is real and feeds back into combat: post-battle XP -> level-ups grant +1 favored stat +1 vigor (so max HP actually grows), wounds persist as hpDamage into the next battle, victory raises the party gods' favor, and gear (weapon/armor/mod bought+equipped in town) genuinely rewrites unit aim/range/damage/AP in party_to_unit.
  - Abilities are fully usable in the interactive battle: ability bar spends AP, target-click flow, heals can revive the fallen, items (bandages/salts/charge) consume inventory, divine ultimates spend the persistent favor pool and empower at 3+ favor.

PARTIAL (9):
  - 5 of 9 stats are DEAD in combat and everywhere else: nimbleness, cognition, knowledge, mien, spirit are never read by any .gd code — party_to_unit reads only vigor/quickness/strength/deftness. design.json's stat descriptions promise dodge (nimbleness), ability accuracy (cognition), crafting/medicine (knowledge), intimidation (mien), fear/magic resistance (spirit) — none implemented. Verified identical in the web build (partyToUnit reads the same 4), so this is dead data faithfully ported, not a port gap.
  - Level-up favored-stat growth is meaningless for 2 of 6 archetypes: hexslinger's favored pair is cognition/spirit and tinkerer's is knowledge/cognition — ALL dead stats — so their level-ups only gain the flat +1 vigor. Preacher (spirit/vigor), lawdog (vigor/mien), drifter (nimbleness/quickness) are 50% dead; only gunslinger (deftness/quickness) gets fully real growth.
  - Creator offers zero stat agency: stats come entirely from fixed pregen blocks; the design.json statBonus dicts are never read by any GDScript — the '+2 Deftness' card text is a display-only string (arch.get('bonuses')). Parity with the web in-game creator, BUT the web repo also contains src/character-creator.html: a standalone 20-point attribute buy + Edges & Hindrances economy (hindrances earn edge points) + JSON export. It is not wired into the web campaign either, and none of it was ported to Godot.
  - Shrine 'Swear to god' is a PORT REGRESSION: town.gd writes p['god'] and announces the god's divine 'granted', but Godot's party_to_unit does not copy 'god' into the battle unit, so battle.gd's u.get('god') is always null and always falls back to ARCH_GOD — the sworn god never changes which favor pool fuels the divine, and victory favor gains also ignore it. The web build honors it (partyToUnit copies god; favor resolution at cast and at victory reads p.god first). In Godot, swearing's only live effect is gating the Clockwork Exo (vulcan-faction armor) in the outfitter swap cycle. Also, the 'granted' divine (design.json gods[].divine, e.g. Forge Strike with dmg/apCost) is unused in BOTH builds — the divine is fixed per archetype.
  - design.json archetypes[].abilities is dead data: tinkerer's 'Deploy Turret' (full turret spec) and the heal amount/range entries are never read — Godot combat uses its own hardcoded ABIL/ABIL2/ABIL_FX tables. Turret has zero implementation in the web battle either (0 hits in scene_battle.js/battle3d.js). No ability choice or learning anywhere: kits are fixed constants, nothing unlocks at level-up.
  - Archetype second weapons (Bowie Knife, Derringer, Pistol Whip-the-weapon, etc.) are dead data: party_to_unit takes only weapons[0] and there is no weapon switching in battle. Same in web.
  - Blessed Vestments '+10% vs divine' is flavor-only: armor contributes only def and speed in party_to_unit; no divine-resist code exists.
  - Stats are invisible to the player: no screen in the Godot build ever shows a character's numbers — creator shows a bonuses string, battle HUD shows name/AP/HP only, town shows gear labels, pause menu has no party sheet. Deftness 8 vs 4 is real math the player can never inspect.
  - 'Initiative' (design.json quickness desc) is only half real: sides act in fixed player-phase/enemy-phase blocks; quickness sorts action order within the enemy phase only — during the player phase you freely click any unit in any order.

MISSING (6):
  - Point-buy stat allocation in the campaign flow — nowhere in Godot (exists only as the unwired standalone web character-creator.html).
